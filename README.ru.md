# KPTV

**Смотрите [KinoPub](https://kino.watch) на Smart TV — веб-клиент
(Samsung Tizen, LG webOS) с бэкендом на FastAPI**

</div>

---

KPTV — клиент KinoPub для Smart TV. Телевизор запускает веб-приложение,
заточенное под пульт (`client/`, ничего устанавливать из магазина приложений не
нужно), а бэкенд на FastAPI (`src/`) стоит между ТВ и API KinoPub — поэтому
связка работает в сетях, где сам KinoPub заблокирован. Телевизор общается только
с вашим сервером.

Возможности: главная с полками и «продолжить просмотр», каталог, поиск с
экранной клавиатурой, папки закладок, история просмотра по устройствам, сезоны
и серии, HLS-плеер с переключением качества/аудиодорожек/субтитров и продолжением
с места остановки.

## Что понадобится

- **Linux-сервер с Docker и плагином Compose**, с публичным IP, в регионе, где
  доступен kino.pub. Дешёвого VPS достаточно.
- **Доменное имя**, указывающее на этот IP — подойдёт бесплатный
  [DuckDNS](https://www.duckdns.org). Один лишь IP не сработает: развёртывание
  только по HTTPS.
- **Учётные данные KinoPub OAuth** (client id/secret) для вашего аккаунта —
  запрашиваются у support@kino.pub.

## Установка

Четыре шага от нуля до работающего сервера.

**1. Направьте домен на сервер.** Создайте DNS-запись и откройте порты 80 и 443
в файрволе (плюс security group облачного провайдера, если есть):

```bash
sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
```

**2. Установите стек:**

```bash
./kptv.sh install
```

Это соберёт образы и создаст `.env` из `.env.example`. Отредактируйте его:

```
SERVER_HOST=<ваш-домен>       # точное имя из шага 1
KP_CLIENT_ID=...              # от support@kino.pub
KP_CLIENT_SECRET=...
```

**3. Выпустите TLS-сертификат.** Одно правило связывает всё воедино: **домен
сертификата, `SERVER_HOST` и адрес, который открывает ТВ, должны совпадать** —
именно поэтому медиа-ссылки клиента остаются same-origin и без mixed content.
`--cert-name kptv` фиксирован (nginx ищет сертификат по этому имени). Сначала
установите certbot (`sudo apt install certbot`):

```bash
sudo certbot certonly --standalone -d <ваш-домен> --cert-name kptv \
    --config-dir "$PWD/data/letsencrypt" \
    --work-dir "$PWD/data/letsencrypt/work" \
    --logs-dir "$PWD/data/letsencrypt/logs" \
    --pre-hook "docker compose stop nginx" \
    --deploy-hook "docker compose restart nginx"
```

Хуки сохраняются вместе с сертификатом, поэтому продление — одна строка в cron:
nginx ненадолго останавливается на время проверки и поднимается с новым
сертификатом, когда тот появится:

```cron
0 3 * * * cd /path/to/kptv && certbot renew --config-dir "$PWD/data/letsencrypt" --work-dir "$PWD/data/letsencrypt/work" --logs-dir "$PWD/data/letsencrypt/logs"
```

**4. Запустите и проверьте:**

```bash
./kptv.sh start
curl https://<ваш-домен>/msx/start.json
```

Ответ JSON означает, что бэкенд поднялся — переходите к телевизору.

## Открытие на ТВ

- **Media Station X (рекомендуется на Tizen):** MSX → Настройки → Start Parameter →
  `https://<ваш-домен>/msx/start.json`. Откроется стартовая страница с
  сфокусированной плиткой KPTV; одно нажатие OK открывает клиент на весь экран.
  (Автооткрытие без нажатия на Tizen невозможно — MSX открывает `link:`-цели
  через `window.open`, который вебвью ТВ блокирует без жеста пользователя.)
- **Браузер ТВ:** откройте `https://<ваш-домен>/client/`.

При первом запуске попросит активацию: код и QR, вводится на kino.pub/device.
После этого идентификатор устройства живёт в localStorage телевизора — больше
логиниться не нужно.

## Панель управления

Устройствами управляет небольшая веб-панель на сервере. Она **недоступна из
интернета**: её порт публикуется только на собственном loopback-адресе сервера
(`127.0.0.1:8001`). Открывается она с вашего компьютера через SSH-туннель:

```bash
ssh -L 8001:localhost:8001 <user>@<ваш-сервер>
```

Что делает эта команда: `-L 8001:localhost:8001` пробрасывает порт 8001 вашего
компьютера на порт 8001 сервера через зашифрованное SSH-соединение. Обратите
внимание: `localhost` справа — это loopback **сервера**, а не вашего компьютера.
Держите терминал открытым и зайдите в браузере на **http://localhost:8001**.
Закончив, закройте терминал (или Ctrl+C) — туннель исчезнет вместе с ним.

Панель показывает устройства с их id, user-agent, статусом активации и размером
истории; открывает историю просмотра каждого устройства (с названиями из
KinoPub) и удаляет отдельные записи; сбрасывает настройки устройства; удаляет
устройство (его локальная история тоже стирается — ТВ придётся активировать
заново). Кнопки в шапке **«Экспорт БД»** и **«Импорт БД»** переносят базу
устройств между серверами: экспорт — это живой SQLite-бэкап, импорт сначала
сохраняет копию текущей базы. Ничто из этого не требует рестарта стека.

Два предупреждения: файл экспорта содержит токены KinoPub всех устройств —
храните его как секрет. И задайте `SERVER_ADMIN_TOKEN` в `.env`, если хотите,
чтобы панель дополнительно спрашивала токен поверх туннеля (один раз за сессию
браузера).

## Повседневное управление

```bash
./kptv.sh status     # контейнеры, здоровье, аптайм, публичный URL
./kptv.sh backup     # консистентный бэкап БД в ./backups/ (безопасно на живом сервере; хранит 10 свежих)
./kptv.sh restart    # пересоздать контейнеры, перечитав .env и conf/
./kptv.sh stop       # остановить всё (данные сохраняются)
```

**Обновление после изменений кода:**

- Изменился бэкенд (`src/`) → снова `./kptv.sh install` (идемпотентен) → `./kptv.sh restart`
- Изменился фронтенд (`client/`) или конфиг nginx (`conf/`) → достаточно `./kptv.sh restart`

Пошаговые инструкции для редких операционных моментов:

## Конфигурация

Всё читается из `.env`; авторитетный список — `src/config/settings.py`.

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `SERVER_HOST` | — (обязательно) | домен, который используют ТВ; должен совпадать с именем сертификата |
| `KP_CLIENT_ID` / `KP_CLIENT_SECRET` | — (обязательно) | учётные данные KinoPub OAuth |
| `KP_PROTOCOL` | `hls4` | предпочтительный протокол стрима: `hls4`, `hls2`, `hls` или `http` (остальные — запасной вариант) |
| `KP_QUALITY` | `1080p` | целевое качество: `2160p`, `1080p`, `720p`, `480p` |
| `KPTV_HTTP_PORT` / `KPTV_HTTPS_PORT` | `80` / `443` | маппинг портов хоста, если эти заняты (только compose) |
| `KPTV_ADMIN_PORT` | `8001` | порт панели на стороне хоста — по-прежнему только loopback; смените, если 8001 занят на сервере (только compose) |
| `SERVER_ADMIN_TOKEN` | — (не задан) | если задан, панель требует этот токен |
| `SERVER_DOCS` | выкл | `true` открывает Swagger/OpenAPI на `/docs` — на сервере в интернете не включайте |

## Разработка

Docker не нужен; Python 3.13+:

```bash
python -m venv .venv
.venv/bin/pip install -r src/requirements.txt
cp .env.example .env   # отредактируйте SERVER_HOST, KP_CLIENT_ID, KP_CLIENT_SECRET;
                       # для dev также SERVER_PORT=1234 (биндится на него)
.venv/bin/python src/main.py
curl http://localhost:1234/msx/start.json   # smoke-проверка, id устройства не нужен
```

Тесты — клиент KinoPub заглушен, каждый тест работает на свежей SQLite в памяти,
без сети и реального аккаунта:

```bash
.venv/bin/pip install -r tests/requirements.txt
.venv/bin/pytest
```

## Безопасность

- Идентификатор устройства (заголовок `X-Device-Id` / параметр `?id=`) **и есть**
  учётные данные: любой, кто его знает, управляет привязанным аккаунтом KinoPub.
  Держите его в тайне. Весь трафик зашифрован TLS, поэтому перехватить id на
  проводе нельзя.
- `/api/v1/proxy` и `/api/v1/subtitle` ретранслируют только запомненные домены
  CDN KinoPub (allowlist) — прокси нельзя использовать для обращения к
  произвольным хостам.
- Панель управления по задумке только на loopback — никогда не публикуйте её
  порт на публичном интерфейсе; SSH-туннель — предусмотренный способ входа.
- `.env` (учётные данные OAuth) и `data/` (токены устройств) в gitignore. Файлы
  бэкапов и экспорта содержат токены — обращайтесь с ними как с секретами.
