# KP-Client — свой полноценный клиент KinoPub для Smart TV

> ⚠️ Исторический документ (архитектурный план эпохи перехода от kp-msx).
> Сохранён как контекст принятых решений. Часть ссылок указывает на удалённый
> MSX-бэкенд (`models/KinoPub.py`, `util/db.py`, `pages/*`, режим `/msx/*`) и
> нереализованные фазы (экран ТВ, UI фильтров, статика через nginx) — сверяйтесь
> с актуальным кодом и `docs/api.md`, а не с этим файлом.
>
> План-черновик. Направление: собственный HTML5-клиент под Smart TV (Samsung Tizen,
> LG webOS) с дизайном уровня флагманских онлайн-кинотеатров. Существующий
> FastAPI-бэкенд kptv (переименованный kp-msx) остаётся как BFF (backend-for-frontend); MSX-режим
> сохраняется параллельно для старых устройств.

## 0. Контекст и обоснование

- MSX ограничивает UI фиксированной сеткой 12×6, предопределёнными элементами и
  шрифтом Roboto; плагины — iframe без ввода. UI уровня Netflix/Кинопоиск в MSX
  недостижим принципиально.
- KinoPub API v1 покрывает всё необходимое: каталог с фильтрами и `conditions[]`,
  поиск, `/items/similar`, трейлеры, закладки-папки, история, watching/marktime,
  watchlist, коллекции, ТВ, серверные настройки устройства (4K/HDR/HEVC, CDN-регион).
- Неофициальная OpenAPI-спека: github.com/aqualhume/kinopub-api (v1 и v1.1).

## 1. Архитектура

```
Smart TV (Tizen/webOS браузер или упакованное web-приложение)
        │  HTTPS: /api/v1/* (JSON), /client/* (SPA), /msx/proxy (медиа)
        ▼
FastAPI backend (существующий, расширенный)
        │  aiohttp: api.service-kp.com/v1
        ▼
KinoPub API + CDN
```

- **Бэкенд** переиспользуется: `models/KinoPub.py` (OAuth-refresh, все методы API),
  allowlist-прокси `routers/proxy.py`, конвертер субтитров SRT→WebVTT,
  device-code регистрация, SQLite (devices, domains). Добавляется новый роутер
  `/api/v1/*` — тонкий адаптер, который отдаёт клиенту уже готовые к рендеру
  агрегаты (один запрос = один экран).
- **Фронтенд** — SPA в `client/` (новая директория, отдаётся nginx как статика).
  Холст 1920×1080 с масштабированием, управление стрелками пульта.
- **Сосуществование**: `/msx/*` продолжает работать как есть; `/client` — новый UI.
  Один сервер, одна БД, одни устройства (device id = идентификатор ТВ).

### Ключевые технические решения (требуют подтверждения на фазе 0)

| Вопрос | Варианты | Предложение |
|---|---|---|
| JS-стек | vanilla JS без сборки / Preact+Vite с транспиляцией в ES5 | Preact (~4 КБ) + Vite, таргет ES5: Tizen 2016 = Chromium M47 |
| Навигация | свой spatial-focus движок / готовый (norigin-spatial-navigation) | свой минимальный движок — полный контроль, мало кода |
| Видео | hls.js везде / нативные плееры (Tizen AVPlay, webOS) | hls.js как база, AVPlay — отдельным адаптером позже |
| Постеры | прямые URL / прокси | через существующий прокси (allowlist уже есть) |
| Авторизация | тот же device-code flow | переиспользовать, экран регистрации — свой |

## 2. Фазы работ

### Фаза 0 — прототип и проверка платформы (1–2 недели)

- Утвердить дизайн-макет (реализован в `client/`).
- Упаковать hello-world web-приложение в Tizen `.wgt` и webOS `.ipk`, проверить на
  реальных ТВ: производительность скролла, воспроизведение HLS через hls.js,
  клавиши пульта (keycodes), кэширование.
- Решить вопрос минимальной поддерживаемой версии ОС (Tizen 2.4+/2016, webOS 3+/2016).

### Фаза 1 — BFF API (`/api/v1/*`)

Новый роутер поверх существующих моделей. Агрегирующие эндпоинты:

- `GET /api/v1/home` — рельсы главной одним запросом: «Продолжить просмотр»
  (watching/movies + watching/serials с обогащением через `items/{id}?nolinks=1`),
  «Новинки» (`items/fresh`), «Популярное» (`items/popular`), коллекции, «Смотрю»
  (подписки с числом новых серий).
- `GET /api/v1/items/{id}` — детальная карточка: метаданные, сезоны/эпизоды с
  прогрессом, `similar`, трейлер, закладочные папки, состояние watchlist.
- `GET /api/v1/catalog` — каталог с фильтрами (type/genre/country/year/sort/
  conditions) и пагинацией курсором.
- `GET /api/v1/search?q=` — поиск + подсказки.
- `GET /api/v1/bookmarks`, `POST /api/v1/bookmarks/toggle` — закладки.
- `GET /api/v1/history`, `POST /api/v1/history/clear` — история.
- `POST /api/v1/progress` — репорт позиции → `watching/marktime`.
- `GET /api/v1/play/{id}?season=&episode=` — резолв ссылки: выбор HLS4, качества,
  субтитры через `/msx/subtitle`, прокси-URL.
- `GET /api/v1/settings` / `POST /api/v1/settings` — per-device настройки
  (4K/HDR/HEVC, прокси, размер постеров), синхронизация с KinoPub device settings.
- `GET /api/v1/tv` — каналы с логотипами и текущей передачей.
- Регистрация: `POST /api/v1/auth/code` + `GET /api/v1/auth/poll` — тот же
  device-code flow, JSON вместо MSX-страниц.

Все ответы — готовые view-модели (название полей под клиент, URL картинок уже
через прокси). Клиент не знает о структуре KinoPub API.

### Фаза 2 — каркас клиента

- SPA-оболочка: роутер экранов (home/catalog/item/search/player/settings),
  история для кнопки «Назад».
- Spatial-navigation движок: фокус, переходы между рядами, запоминание позиции
  при возврате, краевые случаи (пустые рельсы, динамическая подгрузка).
- Базовые компоненты: карточка-постер, широкая карточка с прогрессом, рельс,
  hero-баннер, кнопка, бейджи (рейтинг/4K/новые серии), экранная клавиатура,
  модальные меню, skeleton-загрузка, toast-уведомления.
- Масштабирование 1920×1080 → любой экран; safe-area.

### Фаза 3 — экраны

1. **Главная** — рельсы из `/api/v1/home`, hero с автоподстановкой первого item.
2. **Каталог** — сетка + панель фильтров (жанр, страна, год, сортировка,
   «рейтинг от»), бесконечная прокрутка.
3. **Детальная страница** — бэкдроп, постер, кнопки (Смотреть / Трейлер /
   Буду смотреть / В закладки), сезоны и серии с прогрессом и «просмотрено»,
   актёры, похожие, оценка КП/IMDb.
4. **Поиск** — экранная клавиатура + live-результаты.
5. **Закладки** — папки, создание/удаление, добавление из карточки.
6. **История** — список, «удалить из истории», продолжить с позиции.
7. **ТВ** — сетка каналов с логотипами и текущей передачей.
8. **Настройки** — качество/4K/HDR/HEVC, прокси, регион CDN, размер постеров,
   информация об аккаунте (подписка, устройства, отвязка).
9. **Регистрация** — QR/код + поллинг (по мотивам существующего flow).

### Фаза 4 — плеер

Главное преимущество своего клиента: **UI плеера рисуем сами** (в MSX это было
невозможно — iframe без ввода).

- Собственный плеерный оверлей поверх `<video>` + hls.js: прогресс с превью
  позиции, перемотка ±10с с накоплением (логика `requestedPosition` из hlsx.js),
  буфер, автоскрытие.
- Меню: качество (по высоте рендишена, дефолт 1080p — логика из hlsx.js),
  аудиодорожки (из master playlist), субтитры (WebVTT через `/msx/subtitle`,
  сдвиг таймингов), скорость воспроизведения.
- Сериалы: «Следующая серия» (autoplay по окончании), «Пропустить заставку»
  (если появится источник таймкодов), продолжение с позиции marktime.
- Репорт прогресса каждые 10 с → `/api/v1/progress` → KinoPub marktime.
- Адаптер под нативные плееры платформ (Tizen AVPlay) — отдельной задачей после
  проверки на железе.

### Фаза 5 — упаковка и деплой

- nginx: раздавать `/client/` как статику; SPA-fallback.
- Tizen: `config.xml`, иконки, сборка `.wgt`, установка через developer mode.
- webOS: `appinfo.json`, сборка `.ipk`, установка через developer mode.
- Документация: как подключить ТВ (открыть URL в браузере ТВ / установить пакет).
- `kptv.sh`: учесть клиентские статические файлы в update/backup.

### Фаза 6 — полировка

- Анимации переходов, parallax на hero, lazy-load картинок, skeletons.
- Кэширование ответов BFF (in-memory TTL на стороне FastAPI).
- Предзагрузка соседних экранов/постеров.
- Телеметрия ошибок клиента → серверный лог.
- Локализация (RU сейчас, i18n-слой заложить сразу).

## 3. Риски и открытые вопросы

- **Производительность старых ТВ**: анимации и тени могут тормозить на Tizen 2.x —
  предусмотреть «режим производительности» (отключение эффектов).
- **hls.js на старых движках**: MSE есть не везде (старый webOS) — нужен fallback
  на нативный `<video>` с HLS (как html5x-плеер сейчас).
- **Инвалидация токенов при refresh**: KinoPub гасит старую пару токенов — клиент
  и MSX-режим одного устройства должны работать через один backend-токен (уже так).
- **Лимит ~5 устройств** на аккаунт KinoPub.
- **Региональные блокировки**: сервер должен стоять там, где kino.pub доступен
  (текущая модель деплоя сохраняется).
- **App Store / сертификация**: распространение через developer mode или
  self-host URL в браузере ТВ; официальные магазины — отдельная история.

## 5. Что переиспользуется из kp-msx

- `models/KinoPub.py` целиком (клиент API с refresh-токенами).
- `routers/proxy.py` + allowlist доменов + `/msx/subtitle` (SRT→VTT).
- Device-code регистрация (`routers/registration.py` как референс).
- Логика выбора качества/дорожек и seek-фиксы из `pages/hlsx.js`, `pages/html5x.js`.
- SQLite-слой `util/db.py`, модель Device/DeviceSettings.
- Инфраструктура деплоя: docker-compose, nginx, `kptv.sh`.
